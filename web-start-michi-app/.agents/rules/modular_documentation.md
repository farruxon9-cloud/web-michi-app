# Modular Phase & Component Documentation Rule

## Core Guidelines
1. **Separate Documentation Files**: Every completed phase (Bosqich) and every individual sub-task/section must be saved in its own dedicated Markdown file.
2. **Directory Structure**:
   - `.agents/docs/bosqich_1/`: Phase 1 documentation (1.1, 1.2, 1.3, 1.4)
   - `.agents/docs/bosqich_2/`: Phase 2 documentation (2.1, 2.2, 2.3, 2.4)
   - `.agents/docs/bosqich_3/`: Phase 3 documentation (3.1, 3.2, 3.3, 3.4, etc.)
3. **File Naming Convention**:
   - `<X.Y>_<section_name>.md` (e.g., `1.1_react_router.md`, `3.2_driver_feed.md`, `3.3_job_detail.md`)
4. **Mandatory Content for Each Sub-task File**:
   - **Vazifa Nomi & Tavsifi**: Task name, objective, and requirements.
   - **O'zgartirilgan Fayllar**: Exact list of files created or modified.
   - **Amalga Oshirilgan O'zgarishlar**: Implementation details, design decisions, and code snippets.
   - **Tekshirish & Testlar**: Verification commands, test results, and build status.
5. **Persistence & Learning**: Every time a task or sub-task is completed, update its individual document and ensure all changes are tracked modularly.
